Design notes and assumptions
  • Purpose: let offsite and inbound agents confirm onsite capacity before offering onsite and routing inventory, so we avoid routing into markets without capacity.
  • Read only: no scheduling controls. Booking stays with the onsite team after routing.
  • Input: the provider ZIP, prefilled from site details. Market matching is assumed to happen inside the OSS stored procedure that already feeds the grid.
  • Data: assumes a new OSS endpoint returning open slots (date, start and end time, technician) for a ZIP and date range. Technician names and counts here are made up.
  • Slot length: shown as 2-hour windows for illustration. The real length comes from OSS.
  • Status thresholds (Open 15+ slots, Limited 1 to 14, None 0): placeholders to agree with Ops.
  • Where it shows: offsite and inbound call views, across retrieval methods. Not shown when an onsite scheduler is already open.
  • Not designed yet: refresh cadence, offshore agent visibility rules, and whether technician names are shown to all agent groups.
